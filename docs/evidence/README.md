## 新增与替换

- 每项能力保留一份验收摘要和必要的结构化回执，写明源码 SHA/指纹、产物摘要、
  环境、复现命令、实际结果、跳过/失败项与恢复方法。同一事实不在多个附件重复展开。
- 同一能力的新结果替换旧附件，并更新引用；重要历史差异写进摘要。不要按每次执行
  新建目录。旧附件可通过 Git 历史恢复，无需在当前树保留副本。
- 不提交整树 source manifest、完整依赖/build info、逐包 PASS 日志、重复构建日志、
  浏览器 trace、数据库、压缩包或 VM 磁盘。许可证/供应链发布需要的完整清单应随
  对应发布产物分发；这里保留摘要与定位，不替代发布合规资料。
- 截图只证明视觉状态，最多保留两张代表图。真实与模拟截图必须标注，状态和
  生命周期优先使用结构化回执。不得将清理历史日志写成新一轮测试通过。
- `.local/` 不是永久归档。任务结束清理可再生成日志与临时输出；删除 VM、快照或
  恢复材料前核对进程引用、资源归属和回滚用途。凭据及活跃状态不按日期盲删。

## 仓库预算

`python3 scripts/gpupanel-evidence-budget.py` 只读检查，已接入 Python 契约测试与 CI：

| 范围 | 上限 |
| --- | --- |
| 当前树证据总量 | 1 MiB |
| 验收主题目录 | 8 个 |
| 每主题附件（含 RESULTS.md） | 8 个、合计 256 KiB |
| 单个文本/JSON/摘要文件 | 64 KiB |
| PNG 截图 | 全目录最多 2 张，每张 256 KiB |

允许 `.md`、`.json`、`.sha256`、`.png`。超限时先合并摘要、删除重复内容；只有
明确的新验收需求才在 PR 中解释调整预算。预算检查不验证证据真实性或敏感信息。
